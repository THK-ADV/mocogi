## Findings surfaced but not planned (by maintainer choice, 2026-07-02)

Recorded so they are not re-audited from scratch next run. These are real; they were
deferred because they are larger, riskier, or need product input — not because they were
rejected.

- **No CI pipeline** (`dx`, M). Public repo, every merge relies on manual `sbt test`.
  Highest-leverage foundational fix; should precede broad test additions.
- **Non-transactional / non-idempotent webhook + sync pipelines** (`correctness`, L, HIGH risk):
  `MergeEventHandler`, `git/subscriber/ModuleDatabaseActor`, `git/publisher/CoreDataPublisher`,
  `ModuleReviewService` each perform multi-step DB/GitLab writes with no transaction or
  idempotency guard. Benefits from characterization tests existing first.
- **Zero tests on draft→review→merge workflow and JWT/permission filters** (`tests`, M).
  Highest-churn business paths; `ModuleDraftService`, `ModuleReviewService`, `auth/`,
  `permission/` have no direct specs. `test/git/GitPushEventHandlerSpec.scala` is fully
  commented out.
- **`MergeEventHandler` god actor** (`tech-debt`, L, 645 lines, 12+ deps).
- **Permission resolution 1+N queries** on the authenticated hot path
  (`database/repo/PermissionRepository.scala:124-139`) (`perf`, M). One extra query per
  permission row that carries a teaching-unit context.
- **JWT `aud`/`azp` not validated**, only issuer (`auth/JwtAuthorization.scala:60-70`)
  (`security`, S, MED confidence).
- **`.dockerignore` omits `.env` and `conf/application*.conf`** while `Dockerfile` does
  `COPY . .` — local secrets can be baked into build-stage layers (`security`, S, MED).
  Cheap follow-up if desired: add those paths to `.dockerignore` and rotate any credential
  ever built into an image.
- **Unused dependencies/resolvers**: `specs2`, explicit `jackson-module-scala`, and the
  Akka/Sonatype snapshot resolvers appear unused in `build.sbt` (`tech-debt`, S; MED
  confidence on jackson — verify it is not needed transitively before removing).
- **Duplicated LaTeX row-rendering** across `ExamListsLatexPrinter` and
  `ModuleCatalogLatexPrinter` (`tech-debt`, M, MED confidence).
- **API docs cover ~13 of ~86 routes** (`docs`, M).
- **Re-enable module-catalog change diffs** — `service/artifact/ModuleCatalogService.scala:87`
  hard-codes `moduleDiffs = List.empty` while a working `diffs()` helper sits unused
  (`direction`, M). Product feature currently dark.

## Findings considered and rejected

- **"Require auth on `/identities`, `/examLists`, `/scheduleEntries` reads"**: largely
  by-design. This is a public module-handbook service; `/modules`, `/identities`, and core
  lookups are intentionally unauthenticated `Action`s. Only worth revisiting if the team
  decides `campusId` in the `/identities` payload is too sensitive for anonymous access —
  a product decision, not a code defect.
- **"Add pagination to `/modules`"**: real unbounded read, but existing `po`/`active`
  filters push selection into SQL and current clients depend on full-dataset dumps.
  Higher risk (client-breaking) than leverage; deferred pending a client-contract review.
